## 2. Docker stack

Services in `docker-compose.yml` (compose files: `docker-compose.yml` + `docker-compose.prod.yml` for deploy; `docker-compose.migrate.yml` for host-bound DB cutover; `docker-compose.dev.yml`/`override.yml` for dev):

| Service | Image (built or pulled) | Role | Host port |
|---|---|---|---|
| `reloadsol-db` | `postgres:16-alpine` | Postgres 16, init scripts from `./db/init:/docker-entrypoint-initdb.d:ro`, volume `postgres_data`; mem 768M | none (5432 internal; `127.0.0.1:5432` only under migrate overlay) |
| `reloadsol-bouncer` | `edoburu/pgbouncer:latest` | PgBouncer transaction pool (`POOL_MODE: transaction`, `AUTH_TYPE: scram-sha-256`, max client conn 200); mem 64M | none |
| `web` (`reloadsol-web`) | `Dockerfile.web` (node:20-slim runner; packages pre-built `.next/standalone`) | Next.js API + UI, ONNX shadow scorers; mem 768M | `${WEB_PORT}` (3000; prod binds host :80 via nginx only) |
| `cron` (`reloadsol-cron`) | `Dockerfile.cron` (golang:1.22-alpine → alpine:3.19) | Go scheduler → `POST http://web:3000`; health :8080; mem 128M | `${CRON_PORT}` 8080 (prod: `127.0.0.1:8080:8080` via `ports: !override`) |
| `nginx` (`reloadsol-nginx`) | `nginx:1.27-alpine` | Edge proxy :80 → web (prod only port exposure); mem 64M | 80 (prod) |
| `redis` (`reloadsol-redis`) | `redis:7-alpine` | Caches (RH CLMM pool-state 15s TTL, live tiers), job locks, alert throttles; `--maxmemory 96mb allkeys-lru`; mem 128M | none |
| `social-ingest` (`reloadsol-social-ingest`) | `social-ingest/Dockerfile` (Telethon) | Telegram sidecar → `POST /api/social/ingest`; session dir volume; mem 256M | none |

Health-gated startup order (compose `depends_on: condition: service_healthy`): db healthy → bouncer healthy → web healthy (`wget /api/health` on :3000) → cron (`/health` :8080), nginx, social-ingest. `docker-compose.prod.yml` overrides: web ports `[]`, cron binds `127.0.0.1:8080`, nginx `80:80`, all `restart: always`. **DB-first:** schema comes from `db/init/*.sql` mounted into the db container's init dir — 29 numbered files `00-extensions.sql` … `27-social-chain.sql` (`02-schema.sql` + migrations 03–27; fresh volume applies all on first start; existing volumes get them via `bash scripts/deploy-tencent.sh schema` → `db/init/*.sql` idempotently, or `docker exec … psql < db/init/<file>.sql`). Do **not** run `docker compose down -v` (wipes `postgres_data` + `redis_data`; `docs/OPERATOR_STATE.md` "Docker rebuilds"). Migrations are also applied individually in ops notes (e.g. `db/init/06-mcap-social-patterns-24h.sql`, `07-mcap-drop-peak.sql`, `10-gmgn-strategy-domain.sql`, `13-radar-alert-threads.sql`, `25-rh-clmm-pool-key.sql`).

## 3. Deploy runbook (`scripts/docker-deploy.sh`)

Build while the old container still serves traffic; only rebuild/recreate what changed.

- **Scope flags:** `--web-only` (web **+ social-ingest always-on**), `--cron-only`, `--social-only`, `--db-only` (Postgres + PgBouncer, no npm build), `--infra-only` (nginx/redis), `--all` (web+cron+social), `--clean` (wipe `node_modules`/`.next`), `--full-down` (stop stack before build), `--skip-pull` (CI/git hook), default `--auto` scope from `scripts/docker-scope.sh detect`. npm wrappers: `npm run docker:deploy[:web|:cron|:social|:all]`.
- **Env honored:** `DEPLOY_BRANCH` (default `main`), `WEB_PORT`, `SKIP_BUILD_CHECKS=true` (default true inside the script: `export SKIP_BUILD_CHECKS="${SKIP_BUILD_CHECKS:-true}"`; also skips TS build-error gating in `next.config.js`), `NODE_OPTIONS` heap (`--max-old-space-size=2048` on ≥4GB host, 1536 below), `PUPPETEER_SKIP_DOWNLOAD=true` (deploy default), `NPM_CI_OMIT_DEV=1`, `npm_config_jobs=1`.
- **Flow:** sanitize ports → `start_db_stack` (DB-first) → `verify_env_and_compose` → `ensure-swap.sh` → git fetch/pull → `resolve_scope` → low-memory mitigation (`prepare_low_memory_deploy`: if free <2048MB, stop web/cron/social in scope **before** build, DB stays up) → `npm ci --omit=dev` via `scripts/npm-ci-sync.sh` → `rebuild-native-deps.sh` + `install-build-deps.sh` → `npm run build` on host with `NODE_OPTIONS` → **`verify_standalone_build`** (checks `.next/standalone/server.js`, `.next/static`, required-server-files, and onnxruntime native libs `libonnxruntime.so*` + `onnxruntime_binding.node` under `.next/standalone/node_modules/onnxruntime-node/bin` — deploy fails without them since Pattern/entry ML breaks in Docker) → `compose build` scoped → save previous web image → recreate scoped services (`up -d --no-deps web` keeps cron running; `--no-deps cron` for cron-only) → wait web internal health → if nginx service exists, start nginx+redis and wait edge health with `Host: reloadsol.app` (nginx `default_server` drops unknown Hosts 444) → wait cron `:8080/health` → ensure social-ingest running → **rollback**: if the new web fails health, `rollback_web_container` re-tags the saved previous image and recreates web (CI exits non-zero) → `scripts/warm-cache.sh` after web/infra deploys (GETs `/api/solprice`, `/api/trending`, `/api/trending/stats`, `/api/rpc/health`; non-fatal on misses).
- **Health endpoints:** web `/api/health`, cron `http://127.0.0.1:${CRON_PORT:-8080}/health`, manual worker triggers `POST http://127.0.0.1:8080/trigger/<name>` (needs `X-Trigger-Secret`).
- **Edge nginx reload:** conf in `nginx/` (`nginx.conf` resolver 127.0.0.11; `conf.d/reloadsol.conf` → `web:3000`, plus terminal/flowey/00-default-drop). After conf changes (or 502 with healthy web): `docker exec reloadsol-nginx nginx -t && docker exec reloadsol-nginx nginx -s reload`. With resolver + variable proxy_pass, recreating `web` alone should not require an nginx reload.
- **Low-memory note:** container limits only apply after `--force-recreate`; build-side `npm ci`/`next build` need host swap (`sudo bash scripts/ensure-swap.sh` before first deploy on <4GB VPS).

## 4. Ops runbook

- **DB migrations:** apply via `bash scripts/deploy-tencent.sh schema` (idempotent `db/init/*.sql` + `verify-schema.sh`) or `docker exec -i reloadsol-db psql -U reloadsol -d reloadsol_db < db/init/<file>.sql`. Constraint-fix example (`docs/FIX_STATUS_CONSTRAINT_README.md`): trending `status` check dropped + rebuilt to allow `'waiting'`/`'skipped'`/`'stopped'` (error 23514) — now codified in `db/init/02-schema.sql`; related code fix returns success/error objects instead of throwing inside `Promise.allSettled` (`src/app/api/trending/track/route.ts`).
- **Backup/restore pointers:** `bash scripts/deploy-tencent.sh backup` → `pg_dump` to `backups/reloadsol_db-<ts>.sql`; restore by piping a dump into psql on `reloadsol_db`. Historical hosted-Supabase cutover: `export SOURCE_DATABASE_URL=…` + `bash scripts/deploy-tencent.sh migrate` (pgcopydb; stops writers during migrate; migrate overlay binds db to 127.0.0.1:5432 for host psql).
- **Circuit breaker / real-trading halt:** real trending-bot failures counted consecutively; after `BOT_TRADING_FAILURE_THRESHOLD` the circuit opens and trading halts ~`BOT_TRADING_HALT_MINUTES`, auto-resume. Inspect: `docker exec reloadsol-db psql -U reloadsol -d reloadsol_db -c 'SELECT * FROM bot_trading_state;'`. Sim workers are **not** halted by the real-trading breaker; DLMM pause is separate (Telegram `/pause`). DB-side guards: 60s DB circuit breaker, job locks fail closed when DB down (`PRODUCTION_DEPLOYMENT.md` "Postgres connection errors / circuit breaker").
- **PnL automation setup** (`PNL_AUTOMATION_SETUP.md`): schema `trade_pnl`/`last_pnl_update` on `token_operations` (`db/init/02-schema.sql`); env `PNL_UPDATE_SECRET` (auth `?key=`, Bearer, or legacy `PNL_UPDATE_TOKEN`); Go cron `pnl_update` POSTs `/api/pnl/update` at **02:00 UTC** daily; manual test `curl -X POST "http://127.0.0.1/api/pnl/update?key=…"` or from cron container via `http://web:3000`. It fetches last-30-day trading records, groups by wallet, matches buys/sells, updates `token_operations.trade_pnl`.
- **Price API integration notes** (`PRICE_API_INTEGRATION.md`): `/api/tokens/prices` is the central price source (used by TokenSearch UI + batch). Client: 100ms request aggregation, dedup, client cache 90s TTL; server: ~55 req/min budget with 2–5 min cache (~90% hit rate for popular tokens), stale-cache fallback, LRU; "N/A" resilience on failure. Signals/analytics price feeds reference Jupiter `/v4/price` and trending API (`docs/HOW_WE_GET_THE_SIGNALS.md`).
- **Common failures & fixes** (from `PRODUCTION_DEPLOYMENT.md` troubleshooting + `docs/HOW_WE_GET_THE_SIGNALS.md` + `docs/OPERATOR_STATE.md`):
  - **OOM during `npm ci`/build:** deploy script mitigations (skip Puppeteer download, `npm ci --omit=dev`, `NODE_OPTIONS` heap cap, `free -h`/`dmesg` on failure, automatic web rollback). If web container OOMs at runtime, raise web to 896M–1G in compose and `--force-recreate`.
  - **PgBouncer / DB connection errors:** verify `DATABASE_URL` → `reloadsol-bouncer`; `bash scripts/deploy-tencent.sh schema`; `docker restart reloadsol-web`; duplicate `WEB_PORT=`/`CRON_PORT=` lines cause Cloudflare 521 / cron bind failures (keep exactly one); `CRON_SERVICE_URL` must stay `http://cron:8080`.
  - **Cache TTL staleness:** Redis caches e.g. RH CLMM pool-state (15s TTL), live tiers, job locks, alert throttles; price cache 2–5 min; client price cache 90s; `scripts/warm-cache.sh` after deploy; cache staleness is expected per-TTL — bust by cache-bypass/refetch endpoints rather than restarts. **Never** `down -v` (wipes Redis + Postgres volumes).
  - **Shyft 401/429/400:** real key (not placeholder), one `SHYFT_API_KEY=` line, `SHYFT_MAX_REQ_PER_SEC=5`, backoff built in; truncated wallet rows re-seeded via `npx tsx scripts/seed-tracked-wallets.ts` + delete `length(address) < 32`.
  - **Cron 401 on SL/TP / wallet-poll timeouts:** pass `TRENDING_TRACKER_SECRET` as `?key=`; cron HTTP timeout 300s for `/api/social/wallet-poll` — redeploy cron after `main.go` change.
  - **Social:** `Ingest OK (200)` in `social-ingest` logs; rollups via `POST /api/social/rollup?key=`; social TTL cleanup every 30m (Go cron → `/api/social/cleanup`).
  - **Real-trading halt:** check `bot_trading_state` (above); sim-only deployments can omit bot-automation env.
